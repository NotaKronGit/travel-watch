# 0003. Источник и импорт справочника городов

- Статус: принято, 2026-09-14.
- Область: географический справочник Cabinet.

## Контекст

Для создания заявки нужны подсказки городов по всему миру без ручного заполнения. Тесты и CI должны работать на фиксированных данных независимо от доступности внешнего источника.

## Решение

- Хранить импортированный справочник в PostgreSQL Cabinet. Географические записи не означают подтверждённое покрытие перевозчиков.
- Получать снимок через интерфейс `catalog.Source`. Рабочая реализация — `GeoNamesSource`, тестовая возвращает небольшой набор записей или ошибку.
- Разделить скачивание и разбор, общую валидацию снимка и транзакционное сохранение через собственный storage с goqu.
- Запускать импорт отдельной командой `sync-cities` того же бинарника. Не связывать его с запуском веб-сервиса, сборкой образа или CI.
- Обновлять города по ID источника с сохранением внутренних UUID, сохранять отсутствующие записи неактивными. Публиковать снимок атомарно.
- Тестировать внешний адаптер через локальный HTTP-сервер, а сохранение — в PostgreSQL на синтетических данных.

## Последствия

Подсказки смогут работать без внешних запросов на каждое нажатие клавиши. Первая установка требует явного импорта; обновления и контроль их актуальности остаются эксплуатационной задачей. Полная загрузка ограничена размерами и таймаутами; текущий импортёр хранит снимок в памяти.

Источник поставляет географию и варианты названий, но не транспортные коды и не гарантированное русское отображаемое название. API подсказок, языковой выбор названия и интеграции поставщиков остаются отдельными шагами.

Команды, ограничения и атрибуция: [справочник городов](../ops/city-catalog.md).
