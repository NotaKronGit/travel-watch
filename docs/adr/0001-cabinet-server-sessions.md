# 0001. Серверные сессии Cabinet

- Статус: принято, 2026-09-14.
- Область: авторизация Cabinet.

## Контекст

Нужен первый учебный сценарий регистрации и входа. Выход должен прекращать доступ сразу, а frontend не должен хранить доступный JavaScript токен. JWT потребовал бы отдельного решения отзыва токенов; на этом этапе нет потребителей, которым нужна автономная проверка JWT.

## Решение

Cabinet хранит сессии в PostgreSQL. Браузер получает случайный токен в HttpOnly cookie, база хранит только SHA-256 токена. Проверка сессии выполняется в Cabinet при каждом запросе профиля. Сессия живёт 7 суток; выход удаляет её. Используем SameSite=Strict, Secure для HTTPS и проверку Origin вместе с отдельным заголовком для CSRF.

Пароли хешируются Argon2id с уникальной солью. Регистрация пользователя и создание его сессии атомарны. TOTP отложен согласно roadmap.

## Последствия

Авторизация зависит от доступности БД и требует обращения к ней. Нужны удаление истёкших сессий и защита запросов, использующих cookie. Взамен отзыв сессии прост и немедленно виден всем экземплярам Cabinet. Настройки разработки с HTTP на localhost не являются конфигурацией публичного запуска.

## Реализация

- `services/cabinet/internal/auth` — хеширование, RPC и HTTP-защита.
- `services/cabinet/migrations/00001_auth.sql` — пользователи и сессии.
- `frontend/src/authProvider.ts` — адаптер React Admin.
