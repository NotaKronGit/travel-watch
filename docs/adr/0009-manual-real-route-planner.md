# ADR 0009: ручное независимое построение маршрутов

Статус: принято для экспериментального CLI.

Search самостоятельно выбирает узлы по каталогу аэропортов и наблюдениям Яндекса; результаты Gemini и вручную составленные маршруты ему не передаются. Collector выполняет внешние запросы, Search строит схемы и читает только собственную БД.

Для ручного эксперимента Search запускает бинарник Collector и последовательно обменивается ограниченными JSON-строками через stdin/stdout. Версия протокола и DTO находятся в `api/transport`; сервисы не импортируют чужие internal-пакеты. Это локальный адаптер за интерфейсом Provider, а не новый сетевой сервис и не замена планируемых заданий RabbitMQ/наблюдений Kafka. Производственный контракт и доставка остаются отдельной задачей.

По согласованию с пользователем схема может включать предполагаемые наземные переезды. Они явно помечены, не имеют выдуманного времени и сопровождаются предупреждением. Это отдельный экспериментальный результат `realroutes`; требования валидатора расписаний `journeys` не ослабляются. Наличие транспортной связи без дат не доказывает совместимость двух участков.

Пока поддержаны прямой перелёт, поезд + перелёт и два перелёта, в том числе через разные близлежащие аэропорты. Поиск ограничен географией, страницами и бюджетом запросов. Полнота не заявляется; отсутствие результата не доказывает отсутствие маршрута. Автоматический запуск для заявок, сохранение и выдача в Cabinet, инструменты Gemini и проверка времени остаются следующими этапами.

Запуск и точные ограничения: [самостоятельный планировщик](../ops/route-planner.md).
