# ADR 0013: проверка расписаний сохранённых схем

Статус: принято для первого этапа.

## Решение

После сохранения структурированных схем graph отдельный цикл в процессе Search `build-routes` проверяет их по датам через локальный Collector. Метод `departures` дополняет version 1 JSON-протокола: конкретные времена со смещением и время наблюдения источника. Источник — Яндекс Расписания; цены, наличие мест, автоматический пересмотр и Gemini не входят в этот этап.

Search хранит результат в собственной таблице `schedule_checks`. Существующий GetRoutes возвращает дополнительное типизированное поле `schedule_check`; Cabinet проверяет принадлежность заявки до вызова Search, внутренний транспорт остаётся gRPC/mTLS. ЛК читает результат на третьей вкладке. API чтения не запускает работу.

Пакет `schedules` работает с сохранённой топологией `realroutes`, включая цепочки до восьми транспортных участков и варианты железнодорожного подвоза. Синтетическая библиотека `journeys` остаётся отдельной: её вход требует `routes.Topology` и валидацию двух основных участков MVP; расписание также не является предложением с тарифом на конкретное число пассажиров. Правила времени сохраняют ту же семантику: абсолютные моменты, явные запасы, направленные переезды, даты начала поездки в исходном часовом поясе. Согласование модели предложений — будущий этап.

Неизвестные времена переездов оставляют сочетание предварительным. Частичные ответы и лимиты обозначаются явно. Все известные сроки — оценки из конфигурации; успешная проверка времени не гарантирует стыковку или наличие билетов.

## Последствия

Не требуется новый брокер или Redis. Есть отдельные ограниченные бюджеты и таймауты проверки. Аренда, проверка отмены и условная запись защищают от повторных исполнителей; незавершённые задания восстанавливаются после аварии. Состояние расписаний пока не публикуется в Kafka и не заменяет историю построения схем. Существующие активные заявки с результатом graph могут быть проверены после включения обработчика; миграция сама внешних вызовов не делает.
