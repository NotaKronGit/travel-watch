# ADR 0011: независимые источники и завершение общего этапа

Статус: принято. Дополняет [ADR 0010](0010-route-building-progress.md).

## Участники и запуск

`progress.sources` Search задаёт участников новых запусков: `graph`, `gemini` либо оба (по умолчанию). При первом захвате задания набор сохраняется в `route_building.planners`; изменение конфигурации не меняет уже сохранённый набор. Продолжающиеся при миграции старые задания сохраняют единственного участника `graph`.

Один обработчик выполняет одну заявку, внутри неё одновременно запускает не более двух источников. Каждый получает собственную копию исходного события, а не результаты другого источника. Наш алгоритм использует каталог аэропортов и Collector/Яндекс. Gemini использует существующий независимый `Search`: только названия исходных пунктов и лимит вариантов, без графа, промежуточных узлов и подсказанных маршрутов. Цены, расписания и function calling в этот шаг не входят.

Таймаут Gemini ограничивается `gemini.timeout`, весь запуск — `planner.timeout`. Отмена/потеря аренды отменяет контекст обоих вызовов, обработчик дожидается их остановки. Общего распределённого ограничения квот между экземплярами нет: запускать один обработчик.

## Сохранение и барьер завершения

`planner_runs` хранит каждый источник отдельно: этап, попытку, время начала/окончания, число схем, неполноту, ограниченную категорию ошибки и JSON собственного формата. Ответы провайдеров и секреты в события/историю не попадают. Категории: `error`, `timeout`, `unavailable`.

Завершение источника, его событие и, при необходимости, итог всего этапа записываются одной транзакцией под блокировкой задания. Запись разрешена только текущему токену неистёкшей аренды и неотменённой заявке. Повтор завершения источника не создаёт событие.

Пока хоть один участник строит схемы, общий этап остаётся `building`. Когда все закончили:

- Есть схемы хотя бы одного источника: `awaiting_schedules`, с признаком неполноты при ошибках/неполной выборке.
- Схем нет, ошибок нет: `no_routes`.
- Схем нет и есть ошибка/таймаут: `failed`.

Счётчик общего этапа — сумма схем источников без сопоставления и удаления совпадений. Gemini возвращает неподтверждённые предложения и всегда имеет признак неполноты. Совпадение вариантов не означает подтверждённую перевозку.

При аварии уже завершённые источники не вызываются повторно: новая аренда перезапускает только незавершённые. Исчерпание попыток завершает оставшиеся источники ошибкой, сохраняя ранее полученные варианты. Отмена окончательна; незавершённые источники отмечаются отменёнными, поздние результаты игнорируются.

## Контракт и интерфейс

`TripRouteBuildingUpdated` версии 2 использует `planner_id=all` для общего этапа и `graph`/`gemini` для источников. Все события имеют единую возрастающую ревизию заявки. Cabinet сохраняет их все, но обновляет проекцию этапа только по `all`. Ревизия события отдельного источника не мешает применить более раннюю ревизию общего этапа при переупорядочивании доставки.

Исторические события версии 1 (`graph` как весь этап) остаются читаемыми. В истории отображаются источники, длительность, счётчики, ошибки и независимые таймеры. Сами схемы по-прежнему хранятся в Search; API выдачи схем заявки — отдельный шаг.

## Обновление и откат

Сначала остановить старые обработчики Search, применить миграцию Search 00004 и обновить Cabinet (поддержка версии 2), затем запускать новые обработчики. Старый Cabinet отвергает версию 2 без подтверждения Kafka offset. Не запускать старый и новый route builder одновременно.

В Compose ключ передаётся только route-builder через `SEARCH_GEMINI_API_KEY`. Отсутствующий ключ фиксируется как недоступность Gemini; работа graph сохраняется. Для явного запуска только graph использовать `SEARCH_PROGRESS_SOURCES=graph` до первого захвата задания.

Down удаляет отдельные результаты и состав участников. Перед откатом остановить обработчики и сохранить нужные результаты. Старый потребитель не может читать уже опубликованную версию 2: откат одной только схемы БД недостаточен.
