# Проверка покрытия Яндекс Расписаний

Проверено 2026-09-16 существующим тестовым ключом: 20 последовательных HTTP-запросов, все HTTP 200. [Источник — Яндекс Расписания](https://rasp.yandex.ru/). Параметры, время наблюдения, количество записей и до трёх примеров каждого ответа сохранены в [JSON](yandex-coverage.json), без ключа, цен и персональных данных.

Это диагностика покрытия, а не самостоятельное построение маршрутов: пары для проверок заданы вручную. Они не подставляются в граф и не передаются Gemini как ожидаемый путь. Полноту сети, доступность билетов и совместимость стыковок проверка не устанавливает.

## Метод

Через nearest_settlement определены коды семи городов по приблизительным координатам центра. Полученные названия проверены: Курск, Рязань, Москва, Владивосток, Бангкок, Паттайя, Пхукет. Близость точки сама по себе не означает автоматическую привязку станции или аэропорта.

Метод search вызывался без даты, с transfers=false, limit=100. По документации это выдача прямых рейсов на доступные даты, без готовых маршрутов с пересадками. Для аэропортов использованы IATA, для городов — найденные коды Яндекса. Запрошена только первая страница; total — количество записей провайдера, не число ежедневных рейсов, уникальных поездов или независимых направлений.

## Решение и следующий шаг

Яндекс Расписания подходит для первого источника железнодорожных и авиационных участков: на четырёх направлениях получены полезные данные. Одного этого источника пока недостаточно для полного маршрута до конечного города. Для Бангкок → Паттайя и городских трансферов нужен отдельный источник либо явно неподтверждённый участок.

Следующая реализация — адаптер отдельных транспортных связей в Collector с ограниченной пагинацией, таймаутом, различением пустой выдачи, ошибки и неполного покрытия. Для самостоятельного выбора хабов нужен поиск исходящих связей, а не только проверка заранее выбранных пар; этот способ ещё предстоит реализовать и проверить. Затем наш планировщик строит по этим данным самостоятельно, а Gemini запрашивает их через инструменты без получения чужих маршрутов.

Полный импорт, кеширование, регулярные запросы, цены и построение по расписаниям на этом шаге не добавлялись. Проверка выполнена диагностическим скриптом вне приложения; в CI внешние API не вызываются.
