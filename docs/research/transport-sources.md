# Источники аэропортов и авианаправлений

Исследование от 2026-09-16. Статус: исследование завершено; предложенный первый этап каталога OurAirports реализован, см. [инструкцию](../ops/airport-catalog.md). Существующий граф и расписания остаются синтетическими.

## Вывод

Первым источником справочника аэропортов предлагается OurAirports. Для актуальных авианаправлений источник пока не выбран: проверенные варианты имеют ограничения свежести, доступа или использования. Каталог узлов сам по себе не заменяет источник направлений и предложений.

## Сравнение

| Источник | Данные и доступ | Вывод для Travel Watch |
| --- | --- | --- |
| [OurAirports](https://ourairports.com/data/) | Общедоступный CSV, Public Domain, ночные обновления; точность не гарантируется | Подходит для первого справочника аэропортов без ключа |
| [OpenFlights](https://nginx.openflights.org/data) | Обновления базы маршрутов прекратились в июне 2014 года; сам проект называет данные историческими | Не использовать как актуальный граф |
| [Travelpayouts Data API](https://travelpayouts.github.io/slate/) | Регистрация и токен; данные из кэша пользовательских поисков | Возможный источник наблюдений, но не полный список направлений и не подтверждение доступности |
| [Travelpayouts Search API](https://support.travelpayouts.com/hc/en-us/articles/34788165535250-Search-API-usage-rules) | Каждый поиск должен инициироваться пользователем; запрещён автоматический сбор результатов, предусмотрены требования к показу результатов и переходам к покупке | Обычные условия не подходят для фонового мониторинга; до интеграции потребуется согласовать сценарий с поставщиком |
| [Amadeus Self-Service](https://github.com/amadeus4dev/developer-guides) | Официальный репозиторий объявляет предложение deprecated и архивирован 17 июля 2026 года | Не выбирать по старым инструкциям бесплатного подключения; Enterprise требует отдельного изучения |
| [Aviationstack](https://aviationstack.com/faq) | Бесплатный план для знакомства с flight tracking; airline routes относятся к платным возможностям | Кандидат для дальнейшего изучения при допустимости платного доступа; покрытие наших направлений не проверено |

API платных/партнёрских поставщиков не вызывались, аккаунты не создавались. Отсутствие направления в кэше или ответе с неизвестным покрытием не означает отсутствия перевозки.

## Проверка OurAirports

Скачан официальный `airports.csv` в память, без импорта в БД. В снимке: 86 083 записи, 12 723 605 байт (около 12,1 MiB). Это размер CSV, не оценка размера БД.

Найдены все 17 проверяемых кодов: IWA, SVO, DME, VKO, GOJ, UTP, BKK, KZN, AER, DXB, DWC, OMS, IST, SAW, HND, NRT, HNL. Это наличие записей аэропортов, а не подтверждение рейсов между ними.

[Словарь полей](https://ourairports.com/help/data-dictionary.html) содержит ID, коды, координаты, страну, регион, municipality и scheduled_service. В CSV нет IANA timezone и готовой связи с GeoNames ID. `scheduled_service=yes` не задаёт список направлений или доступность рейса на дату.

Сопоставление по municipality недостаточно: NRT указан в Narita, UTP — Rayong, SAW — Pendik, Istanbul. Нельзя автоматически приравнивать административное местоположение к обслуживаемому городу.

## Объём первого этапа каталога

1. Собственный каталог аэропортов Search: внутренний ID, ID источника, IATA/ICAO, координаты, тип, страна/регион, исходное название, дата импорта. IATA не использовать как первичный ключ.
2. Отдельный интерфейс источника каталога, реализации OurAirports и fixture. Не выдавать CSV за существующий routes.Source: его контракт требует транспортных связей.
3. Ручная команда синхронизации с YAML/env, ограничением размера и таймаутом. Полностью проверить снимок перед транзакционной публикацией; при сбое сохранить предыдущие данные. Никаких загрузок при старте сервиса или в CI.
4. Проверка кодов наших направлений, дублей, повреждённого/неполного CSV и повторного импорта. В тестах небольшой зафиксированный набор.
5. Пока только каталог и диагностическая выдача аэропортов. Автоматическое сопоставление городов, реальные перелёты и наземные связи — следующие отдельные шаги.

## Что нужно решить дальше

- Источник отношений «аэропорт обслуживает город» и часовых поясов. Географическая близость годится для кандидатов на сопоставление, но не доказывает транспортную доступность. Search не читает таблицы Cabinet напрямую.
- Поставщик направлений с разрешённым хранением снимков и проверяемым покрытием России и остальных тестовых стран. Для предложений отдельно проверить разрешение на периодические запросы и хранение истории цен.
- Период применимости маршрутов, сезонность, прямой рейс без промежуточных посадок и неполное покрытие.
- Реальные железнодорожные направления и времена наземных переездов. Для Твери нельзя выдумывать авиасегмент, а для Паттайи — считать переезд из BKK или UTP подтверждённым только по расстоянию.

Полные маршруты на реальных данных в рамках этого исследования не проверены.

## Замер справочника станций, 2026-09-16

Для оценки объёма скачан [Trainline stations.csv](https://github.com/trainline-eu/stations). Это преимущественно европейский смешанный каталог станций, городов и остановок, а не полный мировой реестр пассажирских вокзалов. Лицензия источника — ODbL; в проект он пока не интегрирован.

Измерено: 71 804 записи, 76 колонок, CSV 16 193 202 байта (15,44 MiB). Для RU — 27 записей: этот набор нельзя считать достаточным покрытием России. SHA-256 файла: `3edaa96145258b828a55386c422d0df41b1755f2a9074bcccc54e9d19b68a564`.

В локальном PostgreSQL созданы временные таблицы, загружены все строки и измерен `pg_total_relation_size`; затем выполнен ROLLBACK. Рабочие таблицы не менялись.

| Вариант хранения | Измеренный размер |
| --- | --- |
| Основные поля и индексы | 17 899 520 байт, 17,07 MiB |
| Все 76 исходных полей в JSONB с индексом ID | 126 451 712 байт, 120,59 MiB |

Первый вариант содержит UUID, ID источника, название, страну, координаты, timezone, UIC, active и дату импорта; индексы UUID/ID источника, страны, UIC и названия. Второй — отдельный альтернативный способ хранения всей исходной строки, а не добавочный размер первого. Отношения с городами, дополнительные коды поставщиков, локализации, пространственные/поисковые индексы, резервные копии и WAL в оценку первого варианта не входят. Накопление мёртвых версий при обновлениях не измерялось.

Экстраполяция при похожей длине полей и тех же индексах: 500 тыс. записей — около 119 MiB, 1 млн — около 238 MiB для основных полей. Это сценарии ёмкости, не оценка фактического количества станций мира. Точный мировой размер и российское покрытие потребуют выбора соответствующего источника.

Вывод: измеренный объём справочника невелик; важнее выбрать покрытие и набор полей. Не нужно переходить на запросы к внешнему API только из опасения размера таблицы станций.
