# Сборка поездок по расписаниям

Статус: реализована библиотека `services/search/internal/journeys` на синтетических данных. Она не подключена к обработчику Kafka, API или интерфейсу. Реальных источников, бронирования и подтверждения наличия билетов пока нет.

## Вход и результат

`Assemble` получает топологию, результат любого Planner, снимок предложений и длительностей переездов, запрос, политику запасов и лимиты. Перед сборкой кандидаты проходят тот же `routes.ValidateResult`, что результаты Planner: нельзя обойти проверку транспортных связей или правил MVP.

Предложение содержит ID и источник, конкретную связь, отправление и прибытие с часовым смещением, число взрослых, описание тарифа, время наблюдения и необязательную цену. Цена — за указанную группу пассажиров в минимальных единицах валюты; `nil` означает неизвестную цену. На этом этапе сохраняются цены отдельных предложений без сложения разных валют или ранжирования тарифов.

Длительность наземного переезда задаётся для конкретной направленной связи, с источником и временем наблюдения. `Known=false` или отсутствие записи означает неизвестную длительность. Указанное явно известное нулевое значение отличается от отсутствия данных. Длительности — постоянные оценки для тестового снимка; расписания автобусов, часы работы, пробки и доступность трансферов не моделируются.

Результат содержит совместимые поездки с выбранными предложениями, временами участков, началом и концом всей поездки. У промежутков между участками есть смысл: выход, регистрация, запас и ожидание. Они не являются дополнительными транспортными участками. Подробная разбивка и сводные показатели остаются в [roadmap](../roadmap.md#после-кандидатов-показатели-собранного-маршрута).

Все билеты считаются отдельными. Вычисленная совместимость по тестовой политике не делает стыковку защищённой и не гарантирует реальное прохождение контроля.

## Правила времени

Для первого участка:

```text
начало поездки = отправление первого поезда/самолёта
                − время до посадки/регистрации
                − начальный переезд из города
```

Это самый поздний выезд из исходного города при заданной оценке переезда. Точная точка внутри города пока условная. В запросе обе даты включены; проверяется именно начало поездки в часовом поясе исходного города. Внутренне верхняя граница — полночь следующего календарного дня, вычисленная через AddDate, а не добавлением 24 часов. Первый или последующие рейсы могут отправляться уже на следующий день.

Для последующего основного участка:

```text
прибытие предыдущего транспорта
+ выход/получение багажа
+ наземный переезд, если аэропорты или вокзал/аэропорт различаются
+ запас на задержку
+ время до посадки/регистрации следующего транспорта
≤ отправление следующего транспорта
```

Ровно достаточный запас допускается. В одном аэропорту наземного межаэропортового переезда нет, но выход, запас и подготовка к следующему вылету остаются. Смена терминала отдельно пока не моделируется: необходимые затраты должны входить в тестовую политику. Разные аэропорты всегда требуют связи и известного времени переезда.

Максимальная стыковка измеряется от прибытия предыдущего основного транспорта до отправления следующего, включая все операции между ними. Общая длительность ограничивается от выезда из исходного города до прибытия в конечный город после выхода и заключительного трансфера. Каждый запас учитывается один раз; выход после последнего рейса также включается. Все сравнения выполняются по абсолютному времени.

Политика обязательна и передаётся явно: время до посадки и после прибытия отдельно для поезда/самолёта, запас на задержку, максимум стыковки и всей поездки. Значений по умолчанию для реальных перевозок нет. При подключении к процессу Search параметры будут вынесены в YAML/env. Тест использует 10 минут до/после поезда, 60 минут до вылета, 30 минут после прилёта, запас 30 минут, максимум стыковки 18 часов и поездки 48 часов. Это вымышленные условия для проверки кода.

## Полнота и ошибки

- Полнота исходных кандидатов и снимка предложений сохраняется в `InputIncomplete`. Предоставляющий данные код отвечает за покрытие дат и пассажиров; снимок сам не загружает данные.
- Неизвестный переезд исключает кандидата из подтверждённых по времени поездок и выставляет `MissingTiming`. Другие кандидаты продолжают обрабатываться.
- Пустой полный снимок предложений даёт полный пустой результат. Ошибку запроса к поставщику будущий адаптер должен передавать отдельно, а частичный ответ помечать неполным.
- Ошибочные времена, отрицательные длительности/цены, неизвестные связи и повторный ID предложения одного источника отклоняют снимок целиком. Дубликаты предложений должен нормализовать адаптер; здесь они не принимаются как независимые варианты.
- Число взрослых предложения должно точно совпадать с запросом; стоимость одного пассажира не умножается автоматически.
- Время наблюдения сохраняется, но критерий свежести и повторной проверки наличия пока не реализован.

Лимиты ограничивают входные предложения и переезды, количество рассмотренных предложений при переборе (`MaxCombinations`, включая частичные комбинации) и число поездок (`MaxJourneys`). Большой снимок отклоняется; остановка перебора даёт `LimitReached`. Ровно достигнутый лимит поездок не считается усечением, если других подходящих поездок нет. Порядок кандидатов сохраняется, предложения сортируются по отправлению, источнику и ID. Это воспроизводимый технический порядок, не рекомендация лучшего маршрута.

## Тестовые сценарии Иваново → Паттайя

Ни один рейс, тариф или трансфер в наборе не является реальным предложением. Набор фиксирован на 10–11 января 2027 года и не требует интернета.

| Сценарий | Ожидаемый результат |
| --- | --- |
| Местный прямой вылет | Одна поездка с начальным и конечным трансфером |
| Поезд через Москву | Достаточно времени на вокзал → аэропорт; поездка сохраняется |
| Поезд через Нижний Новгород, ранний вылет | Не хватает запаса; сочетание исключается |
| Поезд через Нижний Новгород, вылет после полуночи | Поездка сохраняется, дата второго участка не ограничена исходным днём |
| Самолёт через Москву | Стыковка в одном аэропорту проходит |
| Самолёт через Нижний Новгород | Ранний вылет исключается, ночной сохраняется |
| Прилёт в другой аэропорт Москвы | Без времени переезда — неполный результат; ровно достаточный запас проходит, недостаточный отклоняется |

## Дополнительные независимые направления

Помимо Иваново добавлены четыре отдельных топологии и набора расписаний в `testsource.AdditionalRoutes`. Все связи, времена, тарифы и предложения синтетические; они не утверждают существование реальных рейсов или поездов.

| Направление | Сценарий | Проверяемый исход |
| --- | --- | --- |
| Казань → Сочи | Прямой перелёт, запрос на двух взрослых | Принимается предложение на двоих; предложение на одного исключается |
| Тверь → Дубай через Москву | Поезд, час переезда вокзал → аэропорт, два вылета | Ранний вылет исключается, поздний подходит; валюты отдельных билетов сохраняются без сложения |
| Омск → Стамбул через Москву | Два перелёта через разные аэропорты с переездом 90 минут | Проверяются смена часового пояса и обязательное время межаэропортового переезда; ранний вылет исключается |
| Токио → Гонолулу | Прямой перелёт через линию перемены дат | Прилёт по местной дате накануне вылета допустим по абсолютному времени; другой вылет исключается, поскольку поездка из города начинается до разрешённой даты |

Каждый дополнительный набор даёт ровно одну допустимую поездку с заранее заданными ID предложений и ожидаемым интервалом от начала до конца. Проверяется независимость от порядка предложений. Удаление известного времени начального трансфера в каждом наборе даёт неполный результат без подтверждённой поездки.

```sh
go test -v ./services/search/internal/journeys -run '^TestAdditionalRoutes$'
```

Основной набор даёт пять допустимых поездок. Отдельные проверки покрывают границу стыковки с точностью до наносекунды, переход на летнее время, предложения в UTC, начало поездки накануне рейса, максимальные интервалы, лимиты, повреждённые данные и отмену через context.

```sh
go test -race ./services/search/internal/journeys/... ./services/search/internal/routes/...
go test -v ./services/search/internal/journeys -run '^TestIvanovoSchedules$'
```

Добавлен [эксперимент сравнения с Gemini](../ops/search.md#сравнение-graphplanner-и-gemini) на пяти направлениях. Реальный прогон требует ключа; HTTP-тесты не измеряют качество модели.
