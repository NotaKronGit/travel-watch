# Создание заявки и выбор городов

Статус: согласованы поля первого сценария, мировой охват подсказок и автоматическое наполнение справочника вместо ручного списка. Реализован отдельный импорт GeoNames с тестовым источником и атомарным сохранением справочника. Страница и API подсказок ещё не реализованы.

## Согласованный первый сценарий

Пользователь с активной сессией создаёт заявку на поездку в одну сторону:

- город отправления;
- город назначения;
- первая и последняя допустимые даты отправления;
- число взрослых пассажиров.

Диапазон относится к отправлению всей поездки, а не к датам пребывания. Обе границы включены; одинаковые даты означают отправление в один конкретный день. Город пересадки подбирает система в рамках сочетания поезда и прямого рейса. Дети, обратная поездка и условия уведомления не входят в первую форму.

Подсказки охватывают города по всему миру; список не заполняется вручную. Географический охват формы шире начального покрытия поиска. Доступность города в форме не подтверждает наличие перевозок: предложения должны поступать от источников поиска. Пока источники не подключены, нельзя обозначать выбранное направление как поддерживаемое для реального поиска.

## Предлагаемое поведение формы

Поля «Откуда» и «Куда» работают как поиск с выбором результата. Подсказка содержит название города, регион при необходимости и страну: одинаковые названия не должны создавать неоднозначность. Отдельный обязательный выбор страны не нужен; фильтр по стране можно добавить при расширении покрытия.

После ввода минимум двух символов frontend запрашивает подсказки с небольшой задержкой, отменяет предыдущий запрос и не позволяет устаревшему ответу заменить новые результаты. Поддерживаются выбор клавиатурой и очистка. Изменение текста после выбора сбрасывает ID: произвольный текст не становится выбранным городом.

Загрузка, отсутствие совпадений и недоступность справочника показываются разными состояниями. При ошибке пользователь может повторить запрос. Ошибка сохранения не очищает заполненные поля; повтор после неопределённого результата не должен создавать дубликат заявки.

Сервер получает ID городов, даты и число взрослых. Он заново проверяет сессию, существование и актуальность городов, различие отправления и назначения, корректность диапазона и числа пассажиров. Покрытие поставщиков проверяется отдельно при запуске поиска; неизвестное покрытие не считается поддержкой. Выбор из подсказки не заменяет серверную проверку. Владелец заявки определяется по сессии, а не из параметров frontend.

## Источник справочника

Команда `make cities-sync` импортирует мировой справочник GeoNames в PostgreSQL Cabinet. [GeoNames](https://www.geonames.org/export/) предоставляет выгрузки географических данных по лицензии CC BY с указанием источника. Названия и варианты написания импортируются заранее; ввод пользователя не вызывает обращения к внешнему API. Версию и происхождение импортированных данных нужно сохранять, атрибуцию — показывать в интерфейсе и документации данных.

По умолчанию используется `cities500.zip`: населённые пункты с населением более 500 человек и некоторые административные центры. Это мировой охват, но не все населённые пункты. `countryInfo.txt` содержит страны и их коды, основной файл городов — варианты названий и часовые пояса. Русские названия городов и стран импортируются из `alternateNamesV2` в `name_ru`; города без перевода пропускаются до записи в БД. Исходное `name` сохраняется для сопоставления и поиска. Варианты написания сохраняются для будущего поиска. Форматы и критерии включения описаны в [документации выгрузок](https://download.geonames.org/export/dump/readme.txt).

Импорт выполняется отдельной командой, а не при запуске веб-сервиса. Настройки и проверки описаны в [инструкции импорта](../ops/city-catalog.md). Повторная загрузка обновляет записи по ID источника без дубликатов и ручного перечисления городов. Проверенная загрузка публикуется целиком; ошибка скачивания или разбора не заменяет рабочий справочник пустым. Исчезнувшие записи нельзя каскадно удалять вместе с заявками: их нужно сохранять для существующих ссылок, исключая из нового выбора. Расписание обновлений определяется при реализации, отдельный постоянно работающий сервис для импорта не требуется.

Cabinet хранит свой справочник; выдача подсказок через ConnectRPC будет реализована вместе с формой. Для первого этапа отдельный сервис справочника не нужен. У города есть устойчивый внутренний ID, ссылка на запись источника, код страны, название, варианты написания и признак доступности в форме. Изменение названия не меняет идентичность города и ранее созданные заявки.

Город, вокзал и аэропорт — разные сущности. GeoNames не подтверждает поддержку поставщика и не заменяет его транспортный справочник. Коды станций, аэропортов и городов конкретных поставщиков сопоставляются отдельно при подключении источников. Межсервисные контракты должны передавать явно согласованные идентификаторы; другие сервисы не читают таблицы Cabinet.

Публичный Nominatim не подходит для подсказок по мере ввода: его [правила](https://operations.osmfoundation.org/policies/nominatim/) запрещают autocomplete. Авиационный справочник одного поставщика также не покрывает автоматически железнодорожную часть маршрута.

## Оставшиеся решения перед реализацией

- Частота обновления справочника; пока импорт запускается вручную.
- Допустимые границы числа взрослых, глубина дат и определение «сегодня» для города отправления.
- Состояние после сохранения до подключения Search: предлагается явно показывать, что заявка сохранена, а поиск ещё не выполняется.

Контракты поиска, запуск проверок и доставка событий — следующий этап, описанный в [roadmap](../roadmap.md). Создание формы не означает реализацию поиска билетов.
