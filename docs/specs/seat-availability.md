# Места и цены поездов

Статус: согласованный ориентир. Реализован первый шаг — контракт поставщика мест и тестовый провайдер в Collector ([описание](../services/collector.md)); остальное не реализовано. Спецификация фиксирует пользовательский сценарий и правила данных для ж/д участков; авиаучастки, покупка и бронирование сюда не входят. Архитектурные решения (передача выбора из Cabinet в Search, контракт Collector) оформляются ADR вместе с соответствующим МР.

## Назначение

Информация о местах — справочная. Приложение показывает, сколько мест и по какой цене было свободно на момент проверки, и даёт ссылку на сайт РЖД; места пользователь выбирает и покупает сам. Приложение не подбирает места за пользователя, не резервирует их и не гарантирует, что они останутся свободными.

## Воронка выбора

```text
1. Стыковки          2. Выбранные              3. Отслеживание
все сочетания   →    места и цены только   →   периодическая проверка
по расписанию        выбранных сочетаний       только отобранных
(без мест)           убрать / вернуться         (затем — уведомления)
                     и добавить ещё
```

1. На вкладке «Стыковки» пользователь видит сочетания из проверки расписаний и отмечает подходящие по удобству.
2. Для каждого добавленного сочетания Search один раз запрашивает места по всем его ж/д участкам. Пока проверка идёт, сочетание помечено «Проверяем места». Пользователь убирает неподходящие или возвращается к шагу 1 и добавляет новые; добавленные проверяются так же.
3. Отобранные сочетания пользователь ставит на отслеживание. Их места проверяются вместе с [периодической перепроверкой расписаний](../ops/schedules.md).

Состояние хранится у каждого сочетания, а не у заявки: не выбрано → выбрано → отслеживается, и обратно. Набор можно менять и после начала отслеживания: добавлять новые сочетания (например, появившиеся при перепроверке или взамен тех, где закончились места) и убирать отслеживаемые.

Отмена или истечение заявки останавливают проверки мест так же, как проверки расписаний.

## Когда выполняются запросы

- Добавление сочетания в выбранные — одна проверка мест этого сочетания.
- Отслеживаемые сочетания — при каждой перепроверке расписаний.
- Открытие вкладок, переход между шагами и повторный просмотр запросов не выполняют; показываются сохранённые данные с временем проверки.
- Выбранные, но не отслеживаемые сочетания повторно не проверяются. Чтобы обновить их данные, пользователь ставит сочетание на отслеживание или убирает и добавляет его снова.

Число выбранных и отслеживаемых сочетаний в одной заявке ограничено параметрами конфигурации Search. Значения определяются по замерам нагрузки на источник; до замеров конкретных значений нет.

## Сводка по участку

Для каждого ж/д участка сочетания показываются:

```text
Поезд 016А Москва → Мурманск, 12 окт, 00:41 → 11:32 (+1 день)
  Плацкарт  34 места (нижних 12)   3 150 – 4 870 ₽
  Купе      11 мест  (нижних 4)    6 900 – 8 200 ₽
  СВ        нет мест
  Проверено 14:05 · Открыть на сайте РЖД
```

Пример выше вымышленный.

- По каждому классу: число свободных мест, из них нижних, диапазон цены одного места «от–до». Цена у РЖД зависит от конкретного места, поэтому одно число не показывается.
- Класс без мест показывается как «нет мест», если источник его вернул. Отсутствие класса в ответе не означает, что в поезде его нет.
- Время проверки показывается всегда. Если с проверки прошло больше 75 минут, рядом выводится красная надпись о том, что данные могли устареть. Порог выбран как часовой интервал перепроверки (`schedules.recheck_interval`) плюс 15 минут запаса, чтобы у отслеживаемых сочетаний надпись появлялась только при пропущенной или задержанной проверке; при изменении интервала порог нужно пересмотреть.
- Ссылка ведёт на поиск поездов на сайте РЖД по станциям и дате, а не на конкретное место. Формат ссылки — страница сайта, а не API; его нужно проверить при реализации, он может измениться без предупреждения.

## Итог по сочетанию

Показывается только оценка «от» по каждому классу: сумма цен N самых дешёвых свободных мест на участке, где N — число пассажиров, сложенная по ж/д участкам. Если источник даёт только диапазон цен класса без цен отдельных мест, оценка — минимальная цена × N с пометкой, что это нижняя граница.

Итог не считается, если хотя бы на одном ж/д участке проверка не выполнена, завершилась ошибкой или мест меньше, чем пассажиров; причина показывается явно. Цены авиаучастков пока не проверяются, поэтому итог называется «стоимость ж/д участков».

## Правила данных

- Ошибка источника, ограничение частоты или неполный ответ не означают «нет мест». Такие результаты сохраняются с причиной и не стирают последние успешные данные — по тому же правилу, что и проверка расписаний.
- «Мест нет» — только успешный полный ответ источника с нулём мест.
- У каждого результата хранятся источник, время наблюдения и признак полноты.
- Нижние и верхние места определяются по данным источника или по стандартной нумерации для купе и плацкарта. В сидячих вагонах деление на нижние и верхние не применяется.
- Состав цены (постельное бельё, сервисные услуги) определяется по данным источника и указывается при реализации; складывать цены с разным составом нельзя.

## Устойчивость выбора

Выбор должен переживать перепроверку расписаний, при которой результат стыковок пересохраняется целиком. Поэтому сочетание опознаётся по содержимому: номер поезда, дата отправления, станции отправления и прибытия каждого участка. Если выбранное или отслеживаемое сочетание больше не найдено в расписании, оно остаётся в списке с пометкой «больше не найдено» и не удаляется молча.

## Владение данными

Согласованный ориентир, оформляется ADR с реализацией:

- Выбор пользователя (выбранные и отслеживаемые сочетания) — данные заявки, хранятся в Cabinet и передаются в Search событием через outbox → Kafka → inbox, как создание и отмена заявки.
- Результаты проверки мест хранятся в Search и читаются Cabinet через существующий gRPC/mTLS.
- Collector получает задания на проверку мест от Search и возвращает нормализованные наблюдения.

## Источник

- В Collector появляется отдельный интерфейс поставщика мест: поезд, дата, станции отправления и прибытия (коды Экспресс-3 уже есть в модели станций) → вагоны, классы, свободные места с номерами, признаком нижнего/верхнего/бокового и ценой, время наблюдения и полнота. Цена указана за одно место, поэтому число пассажиров в запрос не входит: сумма для группы считается в Search. Отдельно от ошибок источника различаются «поезд не найден» и «места не продаются» (продажа ещё не открыта или уже закрыта). Первая реализация — тестовый провайдер на синтетических вагонах.
- Первый реальный адаптер — неофициальный JSON сайта РЖД: только чтение, выключен по умолчанию, со своими лимитами запросов. Он не связан с РЖД официально, формат может измениться без предупреждения, условия использования сайта не проверены. Официального открытого API с местами и ценами не найдено; B2B-агрегаторы (например, «Инновационная мобильность», UFS) требуют агентского договора. Платный или официальный источник подключается как ещё одна реализация того же интерфейса.
- Номера поездов и станции нужно сопоставить между Яндекс Расписаниями и источником мест; способ сопоставления определяется при реализации адаптера.

## Следующий этап: схема вагона

По клику на участок — схема вагонов со свободными и занятыми местами и ценами по сохранённым данным последней проверки. Купе и плацкарт рисуются по стандартной нумерации (купе — 4 места, плацкартный отсек — 4 основных и 2 боковых). Сидячие вагоны без схемы от источника показываются списком мест. Схема — тоже справочная информация на момент проверки.

## Уведомления

Условия уведомлений задаются по классу, а не по отдельным местам: «в классе снова есть не меньше N мест», «мест в классе не осталось», «минимальная цена в классе ниже X». Реализуются вместе с Notification. Отслеживание конкретных мест не планируется: удержать место до покупки пользователь не может.

## Отложено: автоматический подбор мест

Не входит в первую версию, так как пользователь выбирает места сам. Сохранено для возможной подсказки «здесь можно сесть вместе» и для будущих детских тарифов.

При включённой галочке «места рядом», для каждого поезда отдельно:

1. Все места группы — в одном вагоне.
2. Группа из N человек делится на ⌊N/2⌋ пар; при нечётном N одно место отдельное в том же вагоне. Разные пары могут быть в разных купе или отсеках.
3. Пара «рядом» — оба места в одном купе (купе, СВ) или одном плацкартном отсеке, включая два боковых места и сочетание основного с боковым.
4. В каждой паре желательно одно нижнее место; если это невозможно, набор допустим с комментарием.
5. Во всём наборе на поезд обязательно хотя бы одно нижнее место.
6. Из допустимых наборов выбирается набор с наименьшим числом нарушений правила 4, среди них — самый дешёвый.

С появлением детей пара будет означать «взрослый и ребёнок»: каждый ребёнок в паре хотя бы с одним взрослым.

## Порядок реализации

1. Интерфейс поставщика мест в Collector и тестовый провайдер — реализовано.
2. Выбор и отслеживание сочетаний: Cabinet → Search, устойчивый идентификатор сочетания, ADR.
3. Проверка мест в Search для выбранных и отслеживаемых сочетаний, сводка во вкладках, итог «от», ссылка на РЖД.
4. Адаптер неофициального JSON сайта РЖД, выключенный по умолчанию.
5. Схема вагона.

## Открытые вопросы

- Лимиты числа выбранных и отслеживаемых сочетаний — по замерам нагрузки.
- Формат ссылки на сайт РЖД и сопоставление поездов и станций между Яндексом и источником мест.
- Правила «места рядом» для сидячих вагонов — после появления источника со схемами.
- Названия вкладок «Выбранные» и «Отслеживание» — рабочие.
