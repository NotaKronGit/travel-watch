# Локальная разработка

Текущий сценарий: PostgreSQL → Cabinet на Go → кабинет React Admin. Поиск поездок и уведомления пока не подключены.

## Требования

Go 1.26.2, Node.js 24 с npm, Docker с Compose v2 и запущенным daemon. Buf CLI нужен для изменения и проверки Protobuf-контракта; сгенерированный код хранится в Git.

Команды ниже запускаются из корня проекта, кроме явно указанных.

## Первый запуск

Скопируйте `.env.example` в `.env`, если своего файла ещё нет. Задайте три разных локальных пароля: POSTGRES_PASSWORD, CABINET_DATABASE_OWNER_PASSWORD и CABINET_DATABASE_APP_PASSWORD. `.env` исключён из Git.

```sh
make db-up
make migrate
npm --prefix frontend ci
```

В двух отдельных терминалах:

```sh
make cabinet
```

```sh
make frontend
```

Откройте [http://localhost:5173](http://localhost:5173), выберите регистрацию и задайте email и пароль из 15 или более символов. Регистрация сразу открывает кабинет. Выход — в меню пользователя справа вверху.

PostgreSQL слушает только `127.0.0.1:55432`, Cabinet — `127.0.0.1:8080`. Vite проксирует API. Используйте именно `localhost:5173`: допустимый Origin задан в `.env`.

Настройки Cabinet находятся в [services/cabinet/config.yaml](../../services/cabinet/config.yaml), переменные окружения имеют приоритет. Порядок загрузки, единые имена переменных и настройка Docker описаны в [конфигурации Cabinet](configuration.md).

`CABINET_AUTH_COOKIE_SECURE=false` допустим только для локального HTTP; это также значение в поставляемом локальном YAML. Конфигурация публичного развёртывания ещё не подготовлена.

## Данные и миграции

Том `travel-watch_postgres_data` сохраняет пользователей и сессии между перезапусками. `make db-stop` останавливает PostgreSQL, сохраняя данные.

Инициализационный SQL создаёт базу Cabinet и роли только на пустом томе. Изменение паролей в `.env` не меняет пароли существующих ролей: их нужно отдельно менять в PostgreSQL.

`make migrate` запускает Goose с ролью владельца; приложение работает с ограниченной ролью. Миграции встроены в бинарник из `services/cabinet/migrations`. Применённые миграции не редактируются — создаётся следующий SQL-файл.

## Справочник городов

После миграций можно отдельно выполнить `make cities-sync` для импорта GeoNames. Обычный запуск и тесты этого не требуют. Команда использует пароль владельца БД и обращается к интернету; настройки, ограничения и атрибуция — в [инструкции справочника](city-catalog.md).

## Проверки

```sh
make check
npm --prefix frontend test
make test-int
```

`make check`: golangci-lint (включая gosec и govet), Buf lint, Go-тесты с race detector и сборка frontend с проверкой типов. Обычные Go-тесты не требуют БД. Интеграционные требуют запущенного PostgreSQL и корневого `.env`, создают отдельную случайную схему и удаляют её после теста. Отсутствие БД — ошибка, а не пропуск.

Для браузерной проверки оставьте Cabinet запущенным:

```sh
cd frontend
npx playwright install chromium
npm run test:e2e
```

Playwright сам запускает Vite, если порт свободен. Проверяет регистрацию, сохранение входа после обновления, выход, неверный пароль и мобильную страницу. Тест создаёт аккаунт `browser-<timestamp>@example.com` в локальной БД; не запускайте его на production или пользовательском окружении.

Дополнительные браузерные тесты подменяют ответы API тестовыми данными: HTTP 502, обрыв соединения, восстановление проверки сессии, отсутствие сессии и повтор выхода после сбоя. Они проверяют видимое состояние страницы и отсутствие необработанных ошибок JavaScript.

## Контракт API

```sh
make generate
```

Источники: `api/proto`; результат: `gen` и `frontend/src/gen`. Go-генераторы закреплены в `go.mod`, TypeScript-генератор — в `frontend/package-lock.json`. Перед генерацией установите frontend-зависимости. Сгенерированные файлы вручную не редактируются.

## Ограничения этапа

Подтверждение email, восстановление пароля, TOTP и панель администратора пока отсутствуют. Лимиты входа действуют на один экземпляр Cabinet и адрес соединения; production proxy и несколько реплик требуют отдельной настройки.

Frontend закрепляет `decode-uri-component@0.5.0` через `overrides` для исправления DoS (GHSA-vcc3-ghjq-m6fr) в зависимости React Admin. Пересмотреть при обновлении зависимостей. Production-сборка пока имеет крупный JS-bundle; оптимизация загрузки отложена до появления страниц заявок.

## Линтеры Go и безопасность

`make lint` запускает golangci-lint v2.8.0 с конфигурацией `.golangci.yml`, включая gosec, staticcheck, govet, errcheck, проверки HTTP/SQL-ресурсов и передачи контекста. `make gosec` запускает только проверки gosec. Отдельный golint не используется.

Версия закреплена в Makefile; инструмент запускается через `go run` с явной версией без изменения go.mod приложения. Первый запуск скачивает и собирает инструмент, последующие используют кеш Go. Нужен доступ к Go module proxy при первом запуске. В CI используется та же команда через `make check`; findings завершают шаг ошибкой и блокируют сборку образов. Успешный локальный запуск не подтверждает выполнение workflow в GitHub.

Анализируются также тесты с тегом `integration`, но они не выполняются линтером и не требуют PostgreSQL. Сгенерированный код исключён из замечаний. В staticcheck отключены ST1005 (пользовательские сообщения RPC начинаются с заглавной буквы) и QF1003 (необязательная замена if на switch). Подавления gosec допускаются точечно с пояснением; например, строка формата Argon2 не является секретом.
