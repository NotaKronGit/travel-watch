# Конфигурация Cabinet

Cabinet читает `config.yaml` из рабочей папки через Viper. Команды Make указывают [services/cabinet/config.yaml](../../services/cabinet/config.yaml). У каждого сервиса свой файл в его папке. Другой путь задаётся переменной `CABINET_CONFIG`. Файл обязателен; ошибка чтения, неизвестный YAML-ключ или неверный тип значения останавливают запуск. Настройки читаются один раз при старте.

Приоритет: переменные процесса → значения из `.env` → YAML. `.env` загружается из рабочей папки для локальной разработки и не заменяет уже установленные переменные процесса.

Каждый YAML-ключ можно переопределить через `CABINET_` + путь в верхнем регистре с подчёркиваниями:

```sh
CABINET_SERVER_REQUEST_TIMEOUT=8s make cabinet
CABINET_DATABASE_MAX_OPEN_CONNS=20 make cabinet
CABINET_CONFIG=/path/to/config.yaml make cabinet
```

Примеры соответствий:

| YAML | Env |
| --- | --- |
| `server.address` | `CABINET_SERVER_ADDRESS` |
| `server.origin` | `CABINET_SERVER_ORIGIN` |
| `auth.cookie_secure` | `CABINET_AUTH_COOKIE_SECURE` |
| `database.host` | `CABINET_DATABASE_HOST` |
| `database.port` | `CABINET_DATABASE_PORT` |
| `database.app_password` | `CABINET_DATABASE_APP_PASSWORD` |
| `database.owner_password` | `CABINET_DATABASE_OWNER_PASSWORD` |

Других имён для этих настроек нет. Пустое значение переменной является явным переопределением: обязательный пароль нельзя незаметно заменить значением из YAML. `POSTGRES_PASSWORD` — отдельная переменная официального образа PostgreSQL для начальной настройки сервера БД, не параметр Cabinet.

## Настройки

- `server`: адрес, допустимый Origin, таймауты HTTP/RPC и завершения, ограничения размера запросов и заголовков.
- `database`: подключение, отдельные роли приложения и миграций, пул соединений и таймауты. `connect_timeout` задаётся целым числом секунд, например `5s`. `sslmode` относится именно к соединению с PostgreSQL; HTTPS frontend его не защищает.
- `catalog`: HTTPS-адреса выгрузок GeoNames, таймауты скачивания и всего импорта, пределы сжатого/распакованного размера и числа городов. Проверяются для команды `sync-cities`; [инструкция импорта](city-catalog.md).
- `auth`: Secure-cookie, срок сессии, очистка истёкших сессий, окно и число попыток входа, число учитываемых адресов и ограничение параллельного хеширования.

Пароли в общем YAML оставлены пустыми: задавайте их через окружение. `serve` требует только пароль приложения, `migrate` и `sync-cities` — только пароль владельца. Не выводите конфигурацию или строку подключения в логи. Параметры хеширования паролей и требования к паролю остаются правилами авторизации в коде.

`cabinet serve`, `cabinet migrate` и `cabinet sync-cities` — режимы одного бинарника. В Compose это отдельные контейнеры одного образа: `migrate` получает только пароль владельца БД, выполняет миграции и завершается; `cabinet` получает только пароль приложения и запускается после успешных миграций. Отдельного постоянно работающего сервиса миграций нет.

Поставляемый YAML предназначен для локального HTTP: `cookie_secure: false` разрешено только для Origin на localhost/127.0.0.1. Для HTTPS задайте соответствующий Origin и `cookie_secure: true`. Срок сессии из конфигурации применяется к новым сессиям; существующие сохраняют свой срок истечения.

## Docker

Образ Cabinet содержит YAML в `/app/config.yaml`; Compose переопределяет адрес БД, порт, Origin и пароли через `environment`. Для собственного файла смонтируйте его в контейнер только для чтения и укажите его путь в `CABINET_CONFIG`. Ключи процесса нельзя передать контейнеру одним добавлением в `.env.stage_local` или `.env.dev`: их также нужно указать в `environment` Compose либо использовать смонтированный YAML.

Настройки frontend и инфраструктуры Compose (публикуемые порты, образы, тома, health checks) остаются в соответствующих конфигурациях. При изменении адреса/порта Cabinet или лимитов запросов учитывайте настройки Nginx и health checks. Инициализация БД и миграции пока используют роли `cabinet_app`/`cabinet_owner` и базу `cabinet`; смена их имён требует согласованного изменения SQL и настройки PostgreSQL.
