# Импорт справочника городов

Статус: реализована загрузка GeoNames в PostgreSQL Cabinet. API подсказок и страница создания заявки реализованы. Справочник описывает географию, а не доступность перевозок.

## Запуск

В локальном окружении с настроенным `.env`:

```sh
make db-up
make migrate
make cities-sync
```

Последняя команда запускает `cabinet sync-cities`, скачивает `countryInfo.txt`, `cities500.zip` и `alternateNamesV2.zip`, проверяет данные и сохраняет их в БД. Она требует пароль `CABINET_DATABASE_OWNER_PASSWORD`. Роль веб-приложения имеет только право чтения справочника. Повторный импорт выполняется той же командой.

Для базы stage_local используется отдельная команда `make stage-local-cities-sync` с `.env.stage_local`; она запускает контейнер импорта с доступом к интернету. См. [stage_local](stage-local.md).

Команда не включена в `make cabinet`, запуск Compose, сборку Docker-образов или GitHub CI. Отдельный постоянно работающий сервис и расписание пока не добавлены. Контейнер Cabinet содержит ту же команду и конфиг; для её запуска нужны подключение к БД и пароль владельца, как для миграций.

## Конфигурация и объём

Раздел `catalog` в `services/cabinet/config.yaml` переопределяется через env по общим [правилам](configuration.md). Например, `CABINET_CATALOG_HTTP_TIMEOUT=3m make cities-sync`.

По умолчанию: 5 минут на HTTP-запрос, 10 минут на весь импорт, не более 32 МиБ на страны/города и 128 МиБ на распакованный файл городов. Для архива названий отдельные лимиты: 256 МиБ на скачивание и 2 ГиБ на распакованный файл (`max_alternate_download_bytes`, `max_alternate_uncompressed_bytes`). URL задаётся через `alternate_names_url`. Допустимое число городов — от 100 000 до 300 000; нижняя граница проверяется до фильтрации по русскому имени и защищает от неожиданно неполной мировой выгрузки. В БД записывается только отфильтрованный набор; `city_count` и итоговый лог показывают число сохранённых городов. Изменение набора источника может потребовать изменения этих лимитов.

Импорт хранит один ограниченный по размеру снимок в памяти, затем записывает города пакетами по 500 внутри одной транзакции. Архив названий скачивается во временный файл и читается последовательно; после успеха или ошибки файл удаляется. Для него нужно до 256 МиБ свободного места во временной папке. Все языки в БД не копируются: сохраняются русские названия выбранных городов и стран. При принудительном завершении процесса без обработки сигнала временный файл может остаться.

## Обновление и сбои

Интерфейс `catalog.Source` предоставляет метод `Load(ctx)`, который возвращает снимок стран и городов. `GeoNamesSource` отвечает за HTTP и разбор ZIP/TSV; `Importer` — за общую проверку; `storage.ReplaceCatalog` — за транзакционную публикацию. Тестовый источник реализует тот же интерфейс в тестах и не включён в рабочий бинарник.

Импорт проверяет уникальность ID, страны, названия, координаты и часовые пояса. Обновление сопоставляет города по `(source, source_id)`, сохраняя внутренний UUID. Исчезнувшие города остаются в БД с `active=false`. Повторное появление активирует прежнюю запись. Страны сохраняются, в том числе для неактивных городов.

SHA-256 скачанных файлов записывается как версия вместе с временем успешного импорта и числом городов. Это отпечаток содержимого, а не дата публикации источника. Взаимная блокировка в PostgreSQL исключает одновременную публикацию двух снимков; скачивание может выполняться параллельно. Ошибка в любой части транзакции откатывает все изменения, включая флаги активности.

## Проверки без GeoNames

- `make check`: импортёр с тестовым источником, ошибки и отмена; GeoNames-адаптер с маленькими синтетическими ZIP/TSV через локальный `httptest.Server`, HTTP-ошибки, лимиты и таймаут.
- `make test-int`: отдельная временная схема PostgreSQL, фиксированный тестовый источник, повторная загрузка и сохранение ID, деактивация, откат частичного изменения, блокировка публикации и права веб-роли.

Обе команды не скачивают GeoNames. Тестовые названия и записи не представляют реальные маршруты. Полная загрузка из внешнего источника выполняется только явной командой `cities-sync`.

## Источник и лицензия

Географические данные: [GeoNames](https://www.geonames.org/), лицензия [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Форматы и покрытие: [описание выгрузок](https://download.geonames.org/export/dump/readme.txt).

`cities500` охватывает населённые пункты с населением более 500 человек и некоторые административные центры; это не все населённые пункты мира. Русские названия берутся из языковых записей GeoNames; города без русского имени пропускаются до записи в БД. Атрибуция GeoNames показана на странице создания заявки.

## Русские названия

Новая миграция добавляет `name_ru` в города и страны. Применить её и повторить импорт:

```sh
make migrate
make cities-sync
```

`name` сохраняет исходное название. `name_ru` содержит русский вариант; города без такого варианта не добавляются. Для подсказок выбираются только активные города и показывается `name_ru`:

```sql
SELECT name, name_ru AS display_name
FROM catalog_cities
WHERE active
ORDER BY population DESC
LIMIT 20;

SELECT count(*) AS active_cities,
       count(*) FILTER (WHERE name_ru <> '') AS with_russian_name
FROM catalog_cities
WHERE active;
```

Из записей языка `ru` выбирается предпочтительная, затем краткая; при равных отметках — запись с меньшим ID альтернативного названия. Исторические, разговорные и имеющие временной период записи не выбираются для отображения. Текущие русские варианты добавляются в `aliases` без дубликатов для будущего поиска. Порядок строк выгрузки не влияет на выбор отображаемого имени.

Город без перевода не передаётся в storage и не занимает строку в БД. Если перевод появится позже, следующий импорт добавит город. Пустой или повреждённый архив, либо полное отсутствие подходящих русских названий прерывают импорт до записи в БД. Ранее сохранённый город, у которого пропал перевод или который исчез из источника, остаётся неактивным с последним известным русским именем и прежним UUID. Новый город без перевода не создаётся. Пустой результат после фильтрации считается ошибкой и не публикуется.

Коды IATA импортируются из записей `iata` в том же `alternateNamesV2`, только при прямом совпадении ID города. Исторические, датированные и неоднозначные коды не используются. После миграции `00005` выполните `make stage-local-cities-sync` (для локального стейджа), чтобы заполнить новое поле без удаления базы. Полнота транспортных кодов этим источником не гарантируется.
