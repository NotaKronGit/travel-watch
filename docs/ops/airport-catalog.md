# Каталог аэропортов Search

Реализован отдельный справочник OurAirports в БД Search. Он не содержит авианаправлений, расписаний, цен или подтверждённых переездов. Cabinet и его справочник городов не изменяются.

## Локальный запуск

Используются обычные настройки Search из `services/search/config.yaml` и корневого `.env`. Нужны пароли БД Search, ключ внешнего API не нужен.

```sh
make db-up
make search-db-init
make search-migrate
make search-airports-sync
make search-airports-find IATA=IWA
```

`search-airports-find` выводит JSON активных записей по IATA (не более 100, по ID источника). Один код может соответствовать нескольким записям; результат не считается однозначной привязкой к городу. Пустой массив означает отсутствие активной записи в нашем справочнике.

Эти команды запускают локальный код и используют локальную БД, а не БД stage_local. Для контейнерного запуска сначала пересоберите образ Search с текущими изменениями и примените миграции соответствующего окружения; затем можно выполнить `search airports-sync` внутри контейнера. Отдельные команды Make для синхронизации stage_local/dev пока не добавлены.

## Настройки

| YAML `airports` | Значение по умолчанию | Env |
| --- | --- | --- |
| url | Официальный HTTPS CSV OurAirports | SEARCH_AIRPORTS_URL |
| download_timeout | 1m | SEARCH_AIRPORTS_DOWNLOAD_TIMEOUT |
| import_timeout | 5m, весь импорт включая загрузку | SEARCH_AIRPORTS_IMPORT_TIMEOUT |
| max_bytes | 33554432, 32 MiB | SEARCH_AIRPORTS_MAX_BYTES |
| min_rows | 70000 | SEARCH_AIRPORTS_MIN_ROWS |
| max_rows | 200000 | SEARCH_AIRPORTS_MAX_ROWS |
| min_retained_percent | 90 | SEARCH_AIRPORTS_MIN_RETAINED_PERCENT |

URL предназначен для доверенного зеркала того же формата и источника; HTTPS обязателен, перенаправления запрещены. Повторов скачивания нет. Резкое сокращение проверяется относительно числа записей последнего успешного импорта. Изменять порог следует после проверки источника, а не автоматически при каждой ошибке.

## Хранение и гарантии

- `catalog_airports`: внутренний UUID, числовой ID OurAirports, ident, исходное название, тип, координаты, страна/регион, municipality, IATA/ICAO, scheduled_service, active и время импорта. IATA не является первичным или уникальным ключом.
- `airport_imports`: источник, число записей, время начала загрузки и успешной публикации. Это состояние последнего импорта, не полная история запусков.
- Все типы, включая закрытые аэропорты и записи без IATA, сохраняются. `active` означает присутствие в последнем снимке, а не работоспособность аэропорта. `type=closed` и `scheduled=false` остаются отдельными признаками. Наличие `scheduled_service` не подтверждает рейс на дату.
- Нет локализованных названий, GeoNames ID, IANA timezone или автоматической связи с городами. Это следующие этапы.
- Вход полностью проверяется перед записью. Некорректная строка, дубликат ID/ident, отсутствующая колонка, лимит, сетевой сбой или ошибка БД не публикуют частичный снимок.
- Обновление, деактивация исчезнувших записей и метаданные публикуются одной транзакцией. Внутренние UUID сохраняются при повторном импорте, смене кода и возвращении записи.
- Публикации сериализуются блокировкой БД. Выгрузка, начатая раньше уже опубликованной, отклоняется. Дата начала загрузки не доказывает свежесть данных зеркала.
- Защита по количеству не обнаружит все повреждения, например замену данных другим набором того же размера.

## Проверка в БД

Через psql для базы `search`:

```sql
SELECT * FROM airport_imports;
SELECT count(*) AS total, count(*) FILTER (WHERE active) AS active FROM catalog_airports;
SELECT pg_size_pretty(pg_total_relation_size('catalog_airports')) AS catalog_size;
SELECT pg_size_pretty(pg_database_size(current_database())) AS database_size;
```

Синхронизация выполняется только вручную. Старт Search, тесты и CI ничего не скачивают. Периодическое обновление аэропортов и городов запланировано в roadmap; механизм запуска ещё не выбран.

## Проверки и откат

Unit-тесты используют синтетический CSV и HTTP-сервер; интеграционный тест проверяет повторный импорт, стабильность ID, сокращение, устаревшую выгрузку, деактивацию, возвращение и откат при сбое БД в изолированной схеме. Команды: `make check`, `make test-int`.

Миграция `00002_airports.sql` создаёт две таблицы и выдаёт search_app права SELECT/INSERT/UPDATE. Синхронизация не использует пароль владельца. Down удаляет только справочник аэропортов и метаданные его импорта; данные inbox и заявок не затрагиваются. После отката миграции команды каталога работать не будут.
