# Dev из готовых образов

Этот режим скачивает Cabinet и frontend из GHCR без локальной сборки. Незакоммиченные изменения не попадут в приложение. Для проверки текущих файлов используйте [stage_local](stage-local.md).

## Первый запуск и обновление

Нужен Docker с Compose v2. Скопируйте `deploy/dev/.env.example` в `.env.dev`, если файл ещё не создан, и задайте три отдельных пароля. Файл исключён из Git.

```sh
make dev-up
```

Откройте [http://localhost:18081](http://localhost:18081). Команда сначала скачивает все образы; при ошибке скачивания запуск прекращается. Затем запускает контейнеры без сборки и повторного скачивания: PostgreSQL → миграции → Cabinet → frontend, с ожиданием готовности. Повторный `make dev-up` обновляет стенд до опубликованной версии. Миграции и отправитель outbox используют тот же образ, что Cabinet. Параллельно запускается Kafka, одноразовый `kafka-init` создаёт топик, после чего отправитель начинает обработку очереди.

По умолчанию используются `ghcr.io/notakrongit/travel-watch/cabinet:dev-latest` и `ghcr.io/notakrongit/travel-watch/frontend:dev-latest`. `IMAGE_PREFIX` можно изменить для другого репозитория; имя должно быть в нижнем регистре. В `IMAGE_TAG` можно указать полный SHA опубликованного коммита вместо `dev-latest`, чтобы выбрать конкретную версию обоих компонентов.

До первой успешной публикации CI команда завершится ошибкой скачивания. Для приватных пакетов предварительно выполните `docker login ghcr.io -u <github-login>` и введите токен с `read:packages` и доступом к пакетам в запросе пароля. Не сохраняйте токен в проекте или аргументах команд.

## Управление и данные

```sh
make dev-stop
make dev-restart
make dev-logs
```

Перезапуск использует существующие контейнеры, без скачивания, сборки и запуска миграций. Для обновления образов или конфигурации используйте `dev-up`.

Проект Compose называется `travel-watch-dev`, том БД — `travel-watch-dev_postgres_data`. Kafka использует отдельный том `travel-watch-dev_kafka_data`, без публикации портов. [Гарантии доставки и проверка outbox](outbox.md). Том БД независим от PostgreSQL локальной разработки и stage_local; остановка и обновление его не удаляют. Порт меняется через `DEV_PORT`. Изменение паролей в `.env.dev` не изменяет пароли ролей в существующей БД.

Стенд доступен только через loopback и HTTP. На удалённом dev-сервере его можно открывать через SSH-туннель; публичный HTTPS и автоматический удалённый деплой здесь не настроены. На localhost окружения используют одно имя cookie: проверяйте их в разных профилях браузера.

## Публикация версий

После успешных проверок push в `main` CI публикует оба образа с SHA коммита. Отдельный job `dev-latest` ждёт успешного завершения обеих сборок и переносит тег `dev-latest` на эти образы без пересборки. PR образы не публикуют. Новые push не прерывают уже выполняющийся workflow публикации.

Два тега обновляются последовательно, не атомарно. Обновляйте стенд после успешного завершения job `dev-latest`; для воспроизводимого запуска используйте одинаковый SHA через `IMAGE_TAG`. При сбое продвижения одного из тегов выбирайте SHA успешной сборки или повторите job. Возврат старых образов не откатывает миграции БД.

Сейчас подготовлены файлы workflow и Compose; публикация и запуск именно скачанных из GHCR образов ещё не проверены.

Для нового Compose нужен опубликованный образ Cabinet с командой `publish-outbox`; старый `dev-latest` до слияния этого МР её не содержит. Запуск скачанных образов с новым отправителем нужно проверить после публикации.
