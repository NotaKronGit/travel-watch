# Search

Статус: реализованы приём создания, отмены и истечения заявок из Kafka, собственные БД и inbox, ручное построение кандидатов на реальных транспортных связях. Автоматическое планирование проверок и поиск предложений с ценами пока не реализованы.

Запуск и проверка: [инструкция Search](../ops/search.md). Правила обработки: [ADR 0006](../adr/0006-search-inbox.md).

Search организует проверки и превращает наблюдения поставщиков в составные маршруты и результаты для пользователя.

Для новых заявок добавлена очередь построения схем независимыми источниками graph и Gemini, отдельный `build-routes` и `publish-progress`. Результат каждого источника сохраняется отдельно; общий этап ждёт всех участников. Этапы и счётчики передаются Cabinet через outbox. Это построение до проверки расписаний и цен. Обработчик включается явно. [Запуск и история](../ops/route-building-progress.md), [ADR 0011](../adr/0011-independent-planner-runs.md).

## Планируемая ответственность и данные

- Объединение одинаковых поисков разных пользователей.
- Планирование периодических и ручных проверок.
- Хранение предложений, результатов проверок и истории цен.
- Составление маршрутов с учётом времени и допустимости стыковки.
- Проверка пользовательских условий и формирование событий уведомлений.

Search владеет общими поисками, расписанием проверок, наблюдениями и результатами. Данные заявки, необходимые для обработки, получает из событий Cabinet; исходной заявкой владеет Cabinet.

## Взаимодействия

- Получает изменения заявок из Kafka.
- Выдаёт задания Collector через RabbitMQ.
- Получает наблюдения Collector из Kafka.
- Публикует события уведомлений для Notification в Kafka.
- Предоставляет результаты для кабинета и бота через ещё не определённые контракты.

Планировщик и обработчики могут быть отдельными процессами одного сервиса. При нескольких экземплярах необходимо исключить дублирование планирования.

## Построение маршрутов

Первый шаг проектирования — [узлы, транспортные связи и кандидаты](../specs/route-building.md). Алгоритм в `internal/routes` работает на синтетическом источнике Иваново → Паттайя, находит прямой рейс, поезд + переезд + рейс и два перелёта с пересадкой в одном аэропорту или со сменой аэропорта. Есть ограничения перебора, удаление дублей и явное неполное покрытие. Алгоритм пока не подключён к потребителю Kafka или API; планировщика и запросов к поставщикам нет. Различаем кандидат для проверки и маршрут с конкретными предложениями.

Реализация выбирается через интерфейс `Planner`; `Compare` сравнивает два алгоритма на одном снимке с общей валидацией ([ADR 0007](../adr/0007-route-planners.md)). Есть GraphPlanner и Gemini Planner; отдельная команда `make search-compare` сравнивает их на пяти синтетических направлениях. В обычном потребителе Kafka LLM не вызывается.

В `internal/journeys` добавлена [сборка поездок по синтетическим расписаниям](../specs/scheduled-journeys.md): конкретные предложения, переезды и проверка временной совместимости. Она пока не подключена к событиям и пользовательскому API.

## Открытые вопросы

- Ключ одинакового поиска и связь общего поиска с пользовательскими заявками.
- Состояния проверки и сборка частичных результатов.
- Частота проверок, обработка ручных запросов и поведение при паузе одной из общих заявок.
- Правила сравнения цен и подавления повторных уведомлений.
- Хранение истории и контракт выдачи результатов.

Правила корректности определены в [описании продукта](../product.md), общий поток — в [архитектуре](../architecture.md).

## Каталог аэропортов

Добавлен собственный каталог OurAirports и ручная синхронизация: [инструкция](../ops/airport-catalog.md). Ручной планировщик выбирает аэропорты по координатам; постоянной привязки к городам и обработки каталога через Kafka пока нет.

## Эксперимент на опубликованных транспортных данных

`make search-compare-real` формирует отчёт независимого сравнения четырёх направлений. Gemini получает только направление и самостоятельно предлагает непроверенные схемы. В этом отчёте GraphPlanner пока помечен как недоступный; новая ручная команда к экрану ещё не подключена. Rome2Rio исключён из отчётов. Артефакт показывается в карточке заявки как отдельно выбранный исследовательский пример. [Методика, результаты и воспроизведение](../research/planner-comparison/README.md). Автоматический расчёт заявок ещё не подключён; выполнена [диагностика покрытия Яндекса](../research/yandex-coverage.md).

`make search-plan-route` независимо строит схемы из реальных ответов Яндекса в `internal/realroutes`: выбирает промежуточные аэропорты и вокзалы, проверяет транспортные связи через Collector, добавляет явно предполагаемые трансферы. Выдаёт JSON с источником, временем наблюдения, ограничениями и предупреждениями. Это отдельный ручной эксперимент без проверки дат и сохранения результатов. [Запуск](../ops/route-planner.md), [ADR 0009](../adr/0009-manual-real-route-planner.md).

Сохранённые схемы доступны через внутренний gRPC с mTLS и пользовательский API Cabinet с проверкой владельца. На карточке доступны панели этапов и независимые страницы источников. [Контракт](../adr/0012-saved-routes-grpc.md), [запуск](../ops/route-results.md).

## Google Flights как источник схем

Наш планировщик дополнен Google Flights/Fli через Collector: использует выбранные аэропорты и до трёх дат из диапазона заявки, сохраняет цепочки аэропортов без номеров рейсов, цен и времени. Яндекс продолжает работать; ошибка нового источника не удаляет его результат. Gemini не получает схемы нашего алгоритма и пока не вызывает этот инструмент. Это обнаружение схем, не проверка стыковок. [Конфигурация и ограничения](../ops/flight-search.md#автоматическое-построение-схем).

Лимит построения теперь относится к схемам: варианты железнодорожного подвоза хранятся вложенно с отдельным пределом. Google Flights получает бюджет проходами по разным парам до повторных дат; географические хабы чередуются по municipality. Детали и совместимость старых результатов — в [ADR 0012](../adr/0012-saved-routes-grpc.md#группировка-железнодорожного-подвоза).

## Проверка расписаний сохранённых схем

Добавлен первый этап получения расписаний Яндекса на дату и проверки стыковок в Search с сохранением результата для вкладки ЛК. Цены и наличие мест не проверяются. [Запуск и ограничения](../ops/schedules.md), [ADR 0013](../adr/0013-timetable-checks.md).
