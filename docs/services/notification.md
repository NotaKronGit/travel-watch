# Notification

Статус: проектирование. Сервис ещё не реализован; ниже описаны предполагаемые границы.

Notification отвечает за Telegram-бота, привязку аккаунтов и доставку уведомлений.

## Ответственность и данные

- Привязка Telegram к аккаунту через одноразовый код с коротким сроком действия; процесс начинается в авторизованном кабинете.
- Доставка уведомлений по событиям Search.
- Команды бота: список заявок, карточка заявки, пауза/возобновление и ссылка на сайт.
- Учёт состояния доставки и повторных попыток.

Notification владеет привязками и состоянием доставки. Заявками владеет Cabinet, результатами — Search. Бот использует общие результаты и не запускает отдельные поиски. Создание заявок в боте отложено.

## Взаимодействия

- Получает события уведомлений Search из Kafka.
- Принимает команды и отправляет сообщения через Telegram API.
- Взаимодействует с Cabinet для привязки и управления заявками; контракты ещё предстоит определить.
- Получает общие результаты поиска для карточек через ещё не определённый контракт.

Доставка требует идемпотентной обработки событий, ограниченных ретраев и backoff. Гарантия exactly-once для отправки в Telegram не предполагается.

## Открытые вопросы

- Выпуск, хранение и погашение одноразового кода, повторная привязка и отвязка.
- Авторизация команд и контракты получения заявок/результатов.
- Модель доставки, обработка неоднозначного исхода отправки и защита от повторов.
- Формат сообщений и обработка недоступного получателя.
