# Cabinet

Статус: реализованы регистрация, вход, выход и получение текущего пользователя через ConnectRPC, таблицы пользователей и сессий в PostgreSQL. Заявки и межсервисные взаимодействия ниже пока планируются.

Подробности: [спецификация авторизации](../specs/cabinet-auth.md), [локальный запуск](../ops/local-development.md).

Cabinet отвечает за веб-кабинет пользователя и управление заявками.

## Ответственность и данные

- Регистрация, вход, пользователи и сессии.
- Создание и изменение заявок, включая параметры поиска, условия уведомления и паузу/возобновление.
- Пользовательский API для frontend, включая доступ к результатам и истории из Search.

Cabinet владеет пользователями, сессиями и заявками. Предложения и история цен принадлежат Search.

## Взаимодействия

- Принимает запросы frontend через ConnectRPC/Protobuf.
- Публикует изменения заявок в Kafka для Search.
- Предоставляет пользователю результаты Search через контракт, который ещё предстоит определить.
- Участвует в начале привязки Telegram из авторизованного кабинета; привязками владеет Notification.

## Открытые вопросы

- Поля и состояния заявки.
- Подтверждение email, восстановление пароля и MFA перед публичным запуском.
- Контракт получения результатов и истории из Search.
- Передача запроса ручной проверки и отображение её состояния.
- Взаимодействие с Notification для привязки Telegram и команд управления заявкой.
